# 商城客户端

这是给商城会员使用的 Vue 3 客户端。现有流程是浏览商品、登录、管理购物车和地址、提交订单、查看订单及微信内付款。本次适配不增加业务页面或新功能。

## 项目分工

- `../ruo-yi-mall`：若依 Java 后端，保存会员、商品和订单，决定权限、库存、价格及最终支付状态。
- `../ruoyi-mall-vue`：运营人员使用的管理后台。
- 本目录 `src/views`：会员页面；`src/api`：现有接口调用；`src/utils/request.js`：凭证、错误和响应处理；`src/utils/contract.js`：请求格式和数据校验。

客户端使用 `/h5` 会员接口与 `/no-auth` 公开接口，不使用管理后台的登录或菜单接口。

## 本地运行

使用 Node.js 22 或以上，在本目录运行：

```powershell
npm ci
npm test
npm run dev
```

打开 http://127.0.0.1:5173 。默认把 `/dev-api` 转发到 `http://127.0.0.1:8080`，需先启动仓库后端及其数据库、Redis，并准备有效会员账号。客户端不会自动创建账号或导入测试 SQL。

后端地址不同时，在未入库的 `.env.development.local` 配置：

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8080
```

生产构建运行 `npm run build`。默认 API 前缀为 `/prod-api`，部署服务器须将此前缀代理到后端并去掉前缀，同时为前端 history 路由配置回退到 `index.html`。也可用 `.env.production.local` 设置 `VITE_APP_BASE_API`。Vite 开发代理不随静态构建发布。

## 接口约定

| 操作 | 后端约定 |
| --- | --- |
| 手机号密码登录 | `POST /h5/account/login`，正文为 Base64(UTF-8 JSON)，Content-Type 为 text/plain |
| 登录凭证 | 从 `{token}` 获取；会员请求携带 `Authorization: Bearer ...` |
| 商品和订单分页 | `page` 从 0 开始；Spring `content/totalElements` 转为页面使用的 `records/total` |
| 删除购物车项 | `DELETE /h5/cart/remove`，正文为 `1,2`，不是 JSON 数组 |
| 地址保存 | 提交数值 `isDefault`，不提交 `memberId` |
| 购物车角标 | 从会员购物车列表汇总有效商品数量，避开原 goodscount 的身份上下文和 COUNT(quantity) 问题 |
| 结算 | 算价传 `receiveAddressId`；下单传 `addressId`；两者都传 `skuList` |
| 积分付款 | `POST /h5/order/orderPay`，传 `payId/type=3`；后台读取订单金额扣积分，返回 `payType=3` 后订单进入待发货 |

## 安全与验证边界

商品详情 HTML 经 DOMPurify 清理；登录过期清除凭证、用户缓存和结算缓存；登录回跳限制为站内地址；结算校验失败不能提交；表单不提交会员归属字段。Base64 只是后端要求的编码，不是加密，生产应使用 HTTPS。

前端检查不能替代服务端授权。原后端地址和购物车部分按 ID 更新/删除的方法未见会员归属条件，会员登录服务的明文参数日志已移除；这些需要后端单独加固，不能用客户端适配宣称已解决。运行联调时补充修复了未绑定微信的普通会员读取个人信息时的空指针；上述权限问题仍需单独处理。

`npm test` 检查编码、分页、地址字段、回跳和非法结算数据。浏览器模拟接口只能验证客户端请求和页面行为；现已通过真实数据库商品查询、会员登录、会员信息接口和首页/详情浏览器验证；积分订单链路的最新实测结果见下方，历史微信支付不在本次范围内。当前依赖审计的 Vite/esbuild 开发依赖告警未通过强制大版本升级处理，开发服务默认仅监听本机。

## 积分支付（2026-09-10）

用户流程：积分活动 → 每日签到 → 选购商品 → 下单 → 积分支付 → 商家发货。
入口为首页顶部“积分活动”和个人中心。商品价格数值按 1:1 作为所需积分（49.00 表示 49 积分），保留两位小数；不调用微信支付。

后台“积分获取规则”中的签到开关和每日积分数直接控制活动；本地每日奖励已从超出数据库上限的数值修正为 100。历史现金订单的消费奖励规则保留，积分订单不赠送消费积分。

`GET /h5/act/integral/activity` 返回账户余额、后台规则和今日领取状态；`POST /h5/act/integral/add` 不接收奖励金额，由后端决定奖励；明细仍使用原积分流水表。支付流水子类型 22，退款入账子类型 13。

支付只使用登录会员自己的订单和后台金额；账户条件扣减与订单状态、流水写入在同一事务中执行。签到使用账户行锁防止重复领取，支付与取消使用订单行锁。积分售后按实付积分全额退回，不支持部分积分退款；未发货订单沿用自动审核流程。

已完成真实 MySQL/Redis/API 流程验证：下单、余额不足、6 请求并发签到、伪造奖励金额、跨会员支付/取消、5 请求并发支付、精确扣分、原路退款与重复退款拦截；Playwright（本机 Edge）验证了电脑端付款、手机端签到和明细。测试会员及测试订单在验证后清理。历史微信订单和其他未改动模块不在本次验证范围内。


## 数字账号注册（2026-09-10）

登录页点击“立即注册”，输入任意11位数字（允许0开头）和6至20位自设密码，即可注册并自动登录。数字仅作为账号标识，不要求真实手机号、短信验证码或微信授权。创建的是商城会员，后台管理员账号仍单独管理。

前端 `src/views/Login.vue` 负责注册/登录切换，`src/api/auth.js` 请求 `POST /h5/register`，正文为 `{ "mobile": "00012345678", "password": "自设密码" }`。服务端 H5MemberService 校验输入、BCrypt散列密码并创建会员，事务保证创建失败回滚。

已有数据库上线前须执行 `ruo-yi-mall/sql/member-account-unique.sql` 一次；本机数据库已执行。唯一索引防止并发重复注册；发现历史重复数据时迁移会失败，需先人工处理，不能直接删除账号。全新数据库的建表脚本已包含索引。

已通过真实浏览器注册→自动登录→个人中心，以及接口重复注册、并发重复注册、非法账号、密码长度、正确/错误密码登录检查。桌面1280×800、移动端390×844验证通过。

## 自助修改头像和用户名（2026-09-10）

进入个人中心 → 编辑资料 → 选择头像/修改用户名 → 保存资料。用户名指展示昵称（1～30个字符），登录仍使用原11位数字账号。支持JPG/PNG图片，最多2MB、宽高最多4096像素；后端验证实际图片内容，居中裁切并重编码为最多512×512的PNG。保存成功后个人中心和顶部用户栏同步更新，取消不会提交。

`POST /h5/member/profile` 接收 multipart/form-data：`nickname` 必填，`avatar` 可选。接口从登录凭证获取用户ID，更新字段仅限nickname/avatar/update_time；不上传图片时保留旧头像。新增头像存于 `ruoyi.profile/avatar/member`，通过现有 `/profile/avatar/member/...` 静态资源路径读取，前端自动加API前缀。本地无需云存储或新增数据库字段。历史头像暂时保留，避免影响缓存中的图片链接。
